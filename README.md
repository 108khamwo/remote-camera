## v0.11.31 — Receiver Master (720p / 1080p, ไฟล์ OBS ถาวร)

- Control Center เป็นที่ตั้ง **ความละเอียด / FPS** หลัก: 720p 30/60 หรือ 1080p 24/30/60 (60 fps เป็นค่าสูงสุดตามการรองรับของกล้อง)
- เมื่อใช้คู่ลิงก์ถาวร หน้า Sender ซ่อนเมนูคุณภาพที่ซ้ำซ้อน เหลือการเลือกกล้อง/ไมค์/เสียง/Zoom และเริ่มหรือหยุดส่ง
- Control Center จดจำค่าคุณภาพแยกตาม Stream ID ใน localStorage ของเบราว์เซอร์ฝั่งควบคุม ส่งคำสั่ง quality ไปยัง Sender ด้วยช่อง Data Hub เดิมเมื่อพบ telemetry ว่าคุณภาพไม่ตรง
- Sender จดจำค่าล่าสุดที่ฝั่งควบคุมสั่งสำหรับคู่ลิงก์นั้นไว้บนมือถือ; การเปลี่ยน 720p/1080p กระทำเมื่อผู้ควบคุมสั่งเท่านั้น ไม่สลับความละเอียดเองเมื่อเน็ตแกว่ง
- **ลิงก์ OBS ถาวรเดิม `r.html?s=...` ยังคงเดิม** ตอนนี้ใช้นโยบายคงที่ Smart Network (สูงสุด 6 Mbps / ต่ำสุด 1.8 Mbps), Buffer 350 ms และ H.264 ระบบปรับ bitrate ฝั่งรับโดยไม่เปลี่ยนความละเอียดบนมือถือ
- ลดกรณีเสียงเงียบ/ถูกกดเมื่อแอปไปอยู่เบื้องหลัง: ปลด software noise gate ก่อนที่ requestAnimationFrame จะถูกระงับ, เมื่อกลับมาหน้าเว็บจึงพยายาม resume AudioContext
- Control Center ล็อกตัวเลือกเครือข่ายสำหรับกล้องที่ใช้คู่ลิงก์ถาวร ไม่ให้ผู้ใช้เข้าใจผิดว่าเปลี่ยนแล้วมีผลถึง OBS ที่ใช้ลิงก์เดิม (ค่าเครือข่ายจะปรับอัตโนมัติใน Viewer เอง)
- กล้องประเภท Native Direct ยังคงใช้การตั้งค่าจาก Native Sender เพราะโปรโตคอลสั่งคุณภาพในรุ่นนี้รองรับ Web Sender เท่านั้น

**ข้อจำกัดทางเทคนิค:** ไม่ได้มี Backend เก็บค่าแต่ละคู่ลิงก์ไว้กลางระบบ ค่า Control Center อยู่บนเบราว์เซอร์ที่ตั้งค่าและคำสั่งส่งผ่าน Data Hub จึงต้องเปิด Control Center ค้างไว้เพื่อส่งค่าให้มือถือใหม่ในครั้งแรก หาก Control Center ปิดอยู่ มือถือที่เคยได้รับคำสั่งจะจำค่าล่าสุดของตัวเอง ส่วนมือถือใหม่เริ่มที่ 1080p/30 จน Control Center ออนไลน์และส่งค่าให้ ค่า OBS สำหรับลิงก์ถาวรใช้ค่า Smart คงที่ ไม่จำเป็นต้องเปิด Control Center เพื่อรับภาพ แต่หากต้องการแก้ค่า OBS เครือข่ายแบบสด ๆ โดยยังใช้ลิงก์เดิมต้องเพิ่ม Shared Config/Signaling เพิ่มต่างหาก

**การทดสอบ:** ตรวจ JavaScript syntax และตรรกะลิงก์ด้วยชุดทดสอบออฟไลน์ได้; ยังไม่ได้ทดสอบส่งสัญญาณ WebRTC จริงผ่าน Firefox ↔ OBS โปรดทดลองจริงก่อนใช้งานงานสำคัญ

## คู่ลิงก์ส่งภาพถาวร v0.11.30

1. เปิด `control.html` บนโดเมน HTTPS ที่ใช้จริง แล้วตั้งชื่อกล้อง กด **สร้างคู่ลิงก์** (ไม่ต้องเปิดมือถือก่อน)
2. คัดลอก **ลิงก์ผู้ส่ง** (`sender.html?s=cam_fixed_...`) ให้ทีมงานล่วงหน้า
3. คัดลอก **ลิงก์ OBS** (`r.html?s=cam_fixed_...`) ลง Browser Source ใน OBS ล่วงหน้า
4. เมื่อถึงเวลา ทีมงานเปิดลิงก์ผู้ส่งที่ได้รับ อนุญาตกล้อง/ไมค์ และกด **ส่งภาพ** ภาพจะปรากฏที่ลิงก์ OBS ประจำช่องนั้น
5. หยุดส่ง/เปลี่ยนมือถือได้ โดยเปิดลิงก์ผู้ส่งเดียวกันอีกครั้ง OBS ไม่ต้องเปลี่ยน URL

### ข้อควรรู้
- แต่ละคู่ลิงก์มีรหัสสุ่ม 128 บิต เก็บเป็น ID ถาวร **ไม่ผูกกับมือถือ** แต่ควรให้คนเดียวใช้งานต่อหนึ่งคู่ในเวลาเดียวกัน (ผู้ส่งสองคนใช้คู่เดียวกันจะชนกัน)
- รหัสลิงก์ทำหน้าที่เสมือนกุญแจ: ผู้ที่ได้รับลิงก์ผู้ส่งอาจส่งภาพเข้าช่องนั้นได้ ไม่มีระบบบัญชีผู้ใช้งาน/รหัสผ่าน กรุณาส่งอย่างระมัดระวัง
- รายการลิงก์ที่แสดงใน Control Center เก็บบน localStorage **เฉพาะเบราว์เซอร์ผู้สร้าง**; ล้างข้อมูลเบราว์เซอร์อาจทำให้รายการหาย แต่ลิงก์เดิมยังใช้ได้ ใช้เมนู “เพิ่มลิงก์เดิมกลับเข้ารายการ” เพื่อกู้กลับ
- สำหรับ v0.11.31 ลิงก์ OBS ถาวรใช้ Smart Network สูงสุด 6 Mbps / 350 ms / H.264 โดย **ไม่เปลี่ยนเมื่อแก้ค่าเครือข่ายใน Control Center** (ลิงก์ OBS แบบเลือกกล้องเดิมยังปรับตามการตั้งค่าเหมือนก่อน)
- เมื่อเปลี่ยนโดเมนหรือ path ของเว็บไซต์ ต้องใช้ URL ใหม่และตั้งค่าให้ Sender/Receiver อยู่ภายใต้โดเมน+path เดียวกัน เพราะ room ถูกคำนวณจากที่อยู่เว็บไซต์
- ใช้งานบน HTTPS เพื่อให้เบราว์เซอร์เปิดกล้อง/ไมค์ และใช้ Clipboard ได้

# ระบบ Live Streaming ระยะไกลผ่านมือถือ v0.11.29 — Mic Volume + Noise Switch + Live Audio Meter

พัฒนาต่อจาก v0.11.27-MIC-SELECT ที่แนบมา โดยปรับ `sender.html`, `sender.js`, `styles.css` และอัปเดต cache `sw.js` เท่านั้น

- **ปรับความดังไมค์ 0–200%** ในหน้า Sender → ตั้งค่า; **100%** เป็นค่าเดิม, 0% เงียบ, 200% ขยายได้สูงสุด 2 เท่า
- ใช้ Web Audio `GainNode` ปรับความดังแบบเรียลไทม์ ทั้งก่อนและระหว่างส่งภาพ โดยไม่ restart กล้องหรือ WebRTC
- **Noise Suppression เปิด/ปิด** ผ่านข้อกำหนดเสียงของเบราว์เซอร์ (`getUserMedia` / `MediaStreamTrack.applyConstraints`); ตรวจสอบสถานะจริงจาก `getSettings()` หากเบราว์เซอร์รายงาน
- ถ้าเบราว์เซอร์เปลี่ยนลดนอยส์ระหว่างส่งไม่ได้ ระบบลองเปิด audio track ใหม่แล้วเปลี่ยนเฉพาะ track เสียงผ่าน SDK `replaceTrack` โดยไม่แตะ track วิดีโอ
- ค่า Gain/Noise บันทึกไว้ในเครื่อง; ค่าครั้งแรก: **Gain 100%, Noise OFF** (คงพฤติกรรมเดิม)
- ถ้า Web Audio ใช้งานไม่ได้ ปล่อยเสียงไมค์เดิมตามปกติและปิดตัวปรับความดัง; ถ้าเบราว์เซอร์ไม่รองรับ Noise Suppression ปิดสวิตช์และแจ้งผู้ใช้
- คงการเลือกไมค์ภายนอก v0.11.27, mute, zoom, control, receiver, OBS links, codec, camera quality และระบบข้อมูลเดิม

## วิธีทดสอบผ่าน Firefox

1. สำรองเว็บไซต์เดิม แล้วอัปโหลดเนื้อหา ZIP ทับไฟล์บนโฮสต์เดิม (HTTPS)
2. เสียบไมค์ภายนอก เปิด `sender.html` ผ่าน Firefox และเลือกไมค์ให้เรียบร้อย
3. เปิด **ตั้งค่า → ความดังไมโครโฟน** จาก 100% เป็น 50% หรือ 150% แล้วฟังเสียงจาก OBS/Receiver เพื่อเปรียบเทียบ
4. สลับ **ลดเสียงรบกวน** ON/OFF แล้วตรวจข้อความสถานะและฟังเสียงจาก OBS (บางเบราว์เซอร์อาจไม่รองรับ)
5. ลองปรับความดัง/Noise ระหว่างส่งภาพจริง แล้วตรวจว่าวิดีโอยังต่อเนื่อง และปุ่มปิด/เปิดไมค์ยังใช้ได้

**หมายเหตุ:** การเพิ่มเกิน 100% อาจทำให้เสียงแตกหากไมค์ดังอยู่แล้ว; Noise Suppression ของเบราว์เซอร์เหมาะกับเสียงพูดแต่มีโอกาสทำให้เสียงดนตรี/บรรยากาศเปลี่ยนไป บางเบราว์เซอร์ไม่เปิดเผยสถานะจริง จึงต้องฟังทดสอบด้วย

**สถานะการทดสอบ:** ตรวจไวยากรณ์และโครงสร้างโค้ดในเครื่องแล้ว แต่ยังต้องทดสอบกับไมค์ภายนอกบน Firefox มือถือและเครื่อง OBS จริง

# ระบบ Live Streaming ระยะไกลผ่านมือถือ v0.11.27 — Microphone Selection

เพิ่มจากไฟล์ต้นฉบับ v0.11.26 ที่ผู้ใช้แนบมา โดยเปลี่ยนเฉพาะ `sender.html`, `sender.js` และเวอร์ชัน service worker (`sw.js`)

- เพิ่มเมนู **ไมโครโฟน (Audio Input)** ในหน้า Sender → ตั้งค่า
- ปุ่ม **ค้นหาไมค์** ขออนุญาตไมค์ (เมื่อยังไม่อนุญาต) แล้วอ่านรายชื่อด้วย `enumerateDevices()`
- ปุ่ม **ใช้ไมค์ที่เลือก** ใช้ `getUserMedia` ร่วมกับ `deviceId.exact` เลือก audioinput; ตัวเลือกอัตโนมัติกลับไปใช้ default ที่เบราว์เซอร์จัดให้
- เปลี่ยนไมค์ระหว่าง LIVE ด้วย `vdo.replaceTrack()` โดยไม่สั่งปิด WebRTC หรือเปลี่ยน Video Track
- แสดงชื่อ audio track ที่เบราว์เซอร์เปิดใช้งานในเมนู
- รักษาสถานะ mute; ปิด track เก่าหลังเปลี่ยนสำเร็จ; หากเปลี่ยนไม่สำเร็จไม่ปิด track เก่า
- ไม่เปลี่ยน Control, Receiver, Native Sender, codec, bitrate, video camera logic หรือกลไกเชื่อมต่อ

## ทดสอบ

1. สำรองไฟล์เว็บเดิมก่อนอัปโหลดไฟล์ ZIP นี้ไปทับเว็บไซต์
2. เปิด `sender.html` ใน HTTPS แล้วเสียบไมค์เข้ามือถือ
3. กดตั้งค่า → **ค้นหาไมค์** และอนุญาตใช้งาน → เลือกชื่อไมค์ → **ใช้ไมค์ที่เลือก**
4. กดส่งภาพ แล้วฟังเสียงผ่าน OBS หรือ Receiver เพื่อยืนยันว่าเสียงมาจากไมค์ที่ต้องการ
5. ลองสลับไมค์ระหว่าง LIVE จากเมนูเดิม แล้วตรวจภาพ/เสียงต่อเนื่อง

**สำคัญ (iOS):** Safari/iOS อาจไม่เปิดเผยไมค์ภายนอก หรือชื่อแทร็กอาจไม่ตรงกับเสียงจริง (ปัญหาระดับ WebKit/OS) เว็บไซต์ไม่สามารถบังคับเลือกฮาร์ดแวร์ที่เบราว์เซอร์ไม่เปิดเผยได้ หากไม่พบ ให้เสียบไมค์ก่อนเปิด Safari ใหม่หรือทดสอบบน Android/เบราว์เซอร์อื่น

## v0.11.43 แชร์ Control Center และ QR

บน Control Center กด **แชร์ Control Center** เพื่อแสดง QR และลิงก์รายชื่อกล้องที่มีในเครื่องนี้ เครื่องปลายทางเปิดลิงก์และยืนยันนำเข้า จะเห็นกล้องโดยไม่ต้องเพิ่มทีละกล้อง ข้อมูลรายชื่อส่งผ่าน URL fragment ไม่ต้องมีเซิร์ฟเวอร์กลาง การแชร์เป็นภาพรวม ณ เวลาที่กดแชร์ ไม่ซิงก์การเปลี่ยนแปลงในอนาคต

ลิงก์ผู้ส่งและ OBS ในแต่ละคู่ลิงก์มีปุ่ม **QR** ข้างปุ่มคัดลอก รวมถึงลิงก์ OBS ที่เลือกอยู่ด้วย QR สร้างในเบราว์เซอร์โดยตรง ไม่ส่งลิงก์ออกไปยังผู้ให้บริการอื่น

**ความปลอดภัย:** ลิงก์แชร์ Control Center บรรจุ Stream IDs ผู้ที่ได้รับลิงก์อาจเข้าถึงภาพและสั่งควบคุมได้ ให้แชร์เฉพาะคนที่เชื่อถือ และระวัง QR ที่ถูกถ่ายภาพ ลิงก์ผู้ส่ง/OBS เดิมไม่ได้เปลี่ยน
